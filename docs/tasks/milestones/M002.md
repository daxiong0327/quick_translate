## 技术方向与公共约定

按照本次技术讨论，以原生 macOS 端上小工具作为实现方向，不建设业务服务端或数据库。

| 能力 | 技术方向 | 约束 |
| --- | --- | --- |
| 语言与界面 | Swift、SwiftUI | 设置与原译文布局；不在视图内混入协议解析 |
| 菜单栏与浮窗 | AppKit | 负责生命周期、位置、焦点和外部点击，结合 SwiftUI 内容 |
| 快捷键与选区 | 系统热键接口、CGEvent、NSPasteboard | 主动触发才复制读取；热键具体接口须在目标系统验证后确定 |
| 模型请求 | URLSession、Swift 并发 | OpenAI 兼容格式，直接请求阿里 API，流式输出、取消和超时 |
| 设置与密钥 | UserDefaults、Keychain | 普通偏好和 API Key 分开；安全存储失败不降级为明文 |
| 构建与测试 | Xcode、XCTest | 先建立实际工程和检查入口，再记录可复现命令及版本 |

最低 macOS、芯片支持范围、Swift 与 Xcode 版本在 T001 核实并登记；模型、地域、默认快捷键及输入长度上限在对应任务落实。T001 先定义配置结构，T002 接入前核对阿里官方地址及可用模型，不硬编码未经核对的旧地址。第一版优先使用系统框架，新增第三方依赖需说明用途。

配置快照包含 HTTPS 服务地址、模型名称和快捷键配置；密钥通过凭据接口读取，不混入可打印的普通设置。翻译会话使用唯一标识隔离过期结果，配置改变只影响下一次请求。模块依赖由初始化入口组装，无跨模块可变全局业务状态。
